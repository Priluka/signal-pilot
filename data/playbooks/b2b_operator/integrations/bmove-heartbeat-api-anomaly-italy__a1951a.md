# Bmove production heartbeat API anomaly alerts affecting parking event transmission to myCicero

> ⚠️ **ONE-OFF INCIDENT — NOT A RECURRING PATTERN**

## What this pattern is

Automated monitoring alerts are generated when the Bmove system detects a potential anomaly in the heartbeat API in the production environment, indicating that parking event transmission to the myCicero parking collector may be disrupted. These tickets are auto-generated by the monitoring system and cover multiple Italian municipalities (e.g., Aquileia, Erto e Casso, Codroipo, Fabriano). The alerts report the timestamp of the last detected heartbeat and request service verification and resolution.

## When this applies

- Automated monitoring system detects a missing or delayed Bmove heartbeat API signal in the production environment
- Heartbeat gap detected for a specific municipality's GSM parking device or Comune integration
- Potential interruption in parking event transmission from Bmove to myCicero parking collector

## Typical resolution flow

1. Monitoring system detects heartbeat API anomaly and records the timestamp of the last successful heartbeat
2. Automated ticket is created in Bmove Support with municipality and last heartbeat details
3. Support team is notified to verify the status of the Bmove service
4. Investigation into whether parking event transmission to myCicero has been interrupted
5. Resolution or service restart performed if an actual outage is confirmed
